# vyshkat

Консольное приложение для приема транспорта после техосмотра, учета
имущества, расчета энергопотребления и поиска техники для новичков.

## Технологии

- Spring Boot;
- JUnit 5 и Mockito;
- JaCoCo.

---

## Архитектура

```text
vyshkat
├── model          доменные объекты и интерфейсы
├── service        операции с парком
├── exception      исключения
├── console        интерактивное консольное меню
└── VyshkatApplication
```

### Интерфесы
`InventoryItem` описывает любой объект на балансе и требует наименование и
инвентарный номер. Его реализуют транспорт и вещи.

`EnergyConsumer` содержит только суточное энергопотребление. Поэтому обычный
велосипед и шлем не обязаны иметь фиктивный нулевой расход, а электросамокат,
электровелосипед и зарядная станция участвуют в энергетическом отчете.

`ServiceCenter` - контракт техосмотра. `DefaultServiceCenter` принимает только исправный транспорт. Spring регистрирует реализацию и передает ее в `FleetService` через конструктор.

### Классы
`Transport` хранит общие свойства транспорта: инвентарный номер, исправность и
простоту для новичка от 1 до 10. `ElectricTransport` добавляет расход энергии.
Конкретные типы представлены классами `Scooter`, `Bicycle` и `ElectricBicycle`.

`Equipment` является базовым классом для вещей. Для демонстрации созданы
`Helmet` и `ChargingStation`.

### Сервисы 
`FleetService` хранит данные в памяти, принимает транспорт только после
техосмотра, проверяет уникальность инвентарных номеров и строит требуемые
выборки и отчеты.

## Правила предметной области

- инвентарный номер обязателен и уникален;
- простота для новичка находится в диапазоне от 1 до 10;
- новичкам подходит принятый транспорт с простотой не ниже 6;
- суточное энергопотребление не может быть отрицательным;
- отклоненный техосмотром транспорт не попадает на баланс;
- сотрудники не являются инвентарными объектами.

## Запуск

В корне репозитория:

```bash
./gradlew :modules:hw-01:bootRun
```

Опционально флаги
```bash
--console=plain --quiet
```

После запуска приложение показывает меню, через которое можно:

1. Добавить транспорт и провести его техосмотр;
2. Поставить шлем или зарядную станцию на баланс;
3. Посмотреть принятый транспорт;
4. Посмотреть все имущество и его инвентарные номера;
5. Посмотреть количество объектов и суммарное энергопотребление;
6. Посмотреть транспорт, подходящий для новичков.

## Тесты и JaCoCo

Запуск всех проверок, включая порог покрытия:

```bash
./gradlew :modules:hw-01:check
```

Только тесты:

```bash
./gradlew :modules:hw-01:test
```

HTML-отчет JaCoCo создается в:

```text
modules/hw-01/build/reports/jacoco/test/html/index.html
```

`FleetServiceTest` передает mock-реализацию `ServiceCenter` через конструктор.
Тесты `acceptsTransportAfterSuccessfulInspection` и
`rejectsTransportAfterFailedInspection` фиксируют оба решения техосмотра и
проверяют факт вызова зависимости.

Тест `selectsBeginnerFriendlyTransport` фиксирует граничное правило: значение
6 включается в список для новичков, а значения меньше - нет.

## SOLID

### O

Новый вид транспорта добавляется наследованием от `Transport` или
`ElectricTransport`. Алгоритмы учета, энергопотребления и поиска техники для
новичков изменять не требуется.

### L

Любой конкретный транспорт используется через `Transport`, любой объект на
балансе - через `InventoryItem`, а потребители энергии - через `EnergyConsumer`. 
Сервисы не проверяют конкретные классы транспорта.

### D

`FleetService` зависит от абстракции `ServiceCenter`, а не от `DefaultServiceCenter`.

## Сознательно ограниченный принцип

`FleetService` одновременно хранит парк в памяти и выполняет отчетные операции. 
Хранение следует вынести в `FleetRepository`, чтобы разделять эту логику.

## Расширения

- Новый вид транспорта требует только нового наследника `Transport` или
  `ElectricTransport`, существующий `FleetService` не меняется.
- Сотрудник не должен реализовывать `InventoryItem`. Для сотрудников можно
  добавить отдельную модель и сервис, не меняя учет имущества.
- Более сложный техосмотр реализуется новым классом `ServiceCenter`, который
  подменяет текущий Spring-бин. Тест `rejectsTransportAfterFailedInspection`

## Использование ИИ

- ИИ использовался для анализа формулировки задания, подготовки первоначальной файловой
